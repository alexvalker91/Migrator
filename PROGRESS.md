# План и Прогресс Разработки Движка Миграции (6 Фаз)

Разработка ведется строго по очереди: 1 Фаза = 1 Сессия -> Компиляция и Unit-тесты -> Отметка `[x]` -> `/clear`.

- [x] **Фаза 1: Domain Layer, Ports & Logging (`showReasoning`)**
  - Мультимодульная сборка: корневой `pom.xml`, модули `migration-engine` (`com.project.migration`) и `migrator` (проект-цель); Maven Wrapper `./mvnw`.
  - Структура пакетов Clean Architecture (`domain`, `application`, `infrastructure`); правила слоёв закреплены `LayerArchitectureTest` (ArchUnit).
  - Доменные перечисления (`Platform`, `ScreenState`, `LlmTier`, `TestMigrationStatus`, `VerificationStatus`, `MigrationStage`, `TestOutcome`, `ComplexityMarkerType`, `PlatformScope`, `IosLocatorStrategy`, `HealingOutcome`, `SavingsSource`).
  - Неизменяемые модели (`TokenUsage`, `ModelPricing`, `LlmCallRecord`, `TelemetrySnapshot`, `CleaningResult`, `ScreenStateKey`, `StateSnapshot`, `ScreenElementMapping`, `ScreenCacheEntry`, `MethodRef`/`FieldRef`/`TestMethodRef`, sealed `CodeChange`, `MigrationTaskDelta`, `TestMethodTask`, `LlmRequest`/`LlmResponse` с sealed `LlmMessage`, `TestRunResult`, `CompilationResult`, `TestMethodReport`, `ClassMigrationReport`, `EngineConfig`, `CommitId`).
  - Sealed `MigrationException` и 6 подтипов (`domain.exception`).
  - Интерфейсы портов в `domain.port`: `LlmClientPort`, `McpClientPort`, `McpClientsPort`, `CacheRepositoryPort`, `SnapshotRepositoryPort`, `CodeAnalyzerPort`, `CodeModifierPort`, `TestRunnerPort`, `GitServicePort`, `ReportGeneratorPort`, `MigrationLoggerPort`.
  - Структурный логгер `LogbackMigrationLogger` (`migration_reports/<Class>/execution.log`): reasoning пишется в файл всегда, блоки `[🧠 LLM REASONING]` выводятся в консоль только при `showReasoning`; флаг `LlmRequest.reasoningRequested` выбирает `-reasoning`-модель.

- [x] **Фаза 2: Фундамент Фреймворка (`XmlPageSourceCleaner`, `BasePage`, `BaseTest`, `JavaParserAstAdapter`)**
  - Полная реализация `XmlPageSourceCleaner` (сжатие в 15–20 раз, белый список атрибутов, метка `offscreen="true"`, семантические зоны `TOP_APP_BAR`/`BOTTOM_NAV_BAR`/`BOTTOM_SHEET`/`scrollable_container`, схлопывание пустых оберток, маскирование секретов) + Unit-тесты.

  - Кроссплатформенный `BaseTest` (Mobitru драйверы, быстрый рестарт `terminateApp`/`activateApp`) и `BasePage` (нативные скроллы, `waitForLoadingToDisappear`, `navigateBack`, `safeHideKeyboard`, `dismissBottomSheetBySwipe`, `openSystemNotifications`, `getCleanText`).
  - Реализация `JavaParserAstAdapter` для чтения и безопасной модификации AST тестовых классов и Page Object'ов.
  - Итог: `application.pagesource` (`XmlPageSourceCleaner` + профили Android/iOS, `SecretMasker`, `TokenEstimator`; сверх спеки без потерь: `resource-id` без префикса пакета приложения, iOS `label`/`value` без дублей, строки списков не схлопываются; синтетические банковские дампы: Android 15.8x, iOS 6.7x). `migrator`: `MobilePlatform`, `DriverFactory` (локальный Appium / Mobitru через `MOBITRU_AUTH_TOKEN` + `mobitru.*`/`<platform>.caps.*`), `BasePage` → `PlatformActions` (`AndroidActions`/`IosActions`), `BaseTest` (`-Dplatform` → suite-параметр), `ios_e2e_suite.xml`. Движок: `FrameworkContract`, `EngineConfig.sourceRoots`/`framework`, `ComplexityMarkerType.INLINE_LOCATOR`, `infrastructure.ast` (symbol solver + фоллбэк по имени/арности; модификация — правки исходника в AST-позициях вместо LexicalPreservingPrinter, который ломал отступы). Фикстура `fixtures/bank-project`.

- [x] **Фаза 4: Dual-MCP Адаптеры и Сервисы Генерации Кода**
  - `DualMcpClientAdapter` (`infrastructure.mcp`): по одному stdio-подпроцессу `appium-mcp` на платформу (Java MCP SDK), лениво при первом `forPlatform`; команда, env (`${VAR}` из окружения движка), `startup_calls` (выбор устройства, создание сессии) и `app_id` берутся из `mcp_servers` конфигурации (версия `appium-mcp` закреплена в `engine-defaults.json`). Таймаут каждого вызова → tool-level ошибка; `getPageSource`, `takeScreenshot`, `restartApp` (terminate + activate) — детерминированные методы порта.
  - `application.agent`: `AgentLoop` (цикл tool-calls поверх `LlmClientPort` с лимитами `agent_loop`: 30 шагов, 8 без прогресса, 150k токенов; исходы `COMPLETED`/`BUDGET_EXHAUSTED`/`STUCK` — значения), `AgentToolbox` (белый список MCP-инструментов на выдаче и на вызове, page source отдаётся только через `XmlPageSourceCleaner`, обрезка длинных ответов, в диалоге остаются 2 последних XML), `FlatJson`.
  - `DeltaAnalyzerService` (Этап 1): AST + вычитание кеша детерминированы; один structured-вызов Tier-3 на класс (экраны Page Object'ов и `ScreenState` тестов), валидация, 1 repair, инвариант «`DEFAULT` для каждого экрана теста». Тесты с `PLATFORM_SPECIFIC_FEATURE` получают `ANDROID_ONLY`; уже смигрированные тесты пропускаются.
  - `SnapshotCollectionService` (Этап 2): проход на тест — чистый рестарт обоих приложений, Android-проход снимает все недостающие состояния теста, `AndroidWalkthrough` (типизированная запись, `migration_reports/<Class>/walkthroughs/`) передаётся iOS-проходу; единственный путь записи слепков — синтетический инструмент `capture_snapshot` (XML не проходит через LLM, существующие слепки не перезаписываются). Недостижимые состояния возвращаются значениями (`UnreachableReason`).
  - `CodeAdaptationService` (Этап 3, без компиляции и коммита): `LocatorMapper` (Tier-2 на пару экран/состояние, проверка предложенного локатора по iOS-слепку — `IosLocatorValidator`, 1 repair → Tier-1, один локатор на поле, конфликты между состояниями), `MethodAdapter` (Tier-1 с reasoning, `CodeAnalyzerPort.inspectBody`: парсится, без остатков Android-конструкций, только существующие/документированные вызовы; 1 repair, иначе `ManualAdaptation`), `InsertCallBefore` со `scrollToElementByText` для `offscreen="true"`, группы `android-only`; пакетное применение с откатом на поштучное; кеш — `UNVERIFIED`.
  - Расширения портов: `CodeAnalyzerPort` (`inspectBody`, `statementsUsingField`, `detectComplexityMarkers(TestMethodRef)`, `testSource`, `setupMethodSources`), `McpClientPort.restartApp`, новый `WalkthroughSinkPort` (`JsonWalkthroughSink`); `LocatorField.collection`, `MigrationTaskDelta.screenOfClass`. Промпты — ресурсы `prompts/*.md` (`PromptTemplates`).
  - Тесты: фейковый stdio MCP-сервер, `ScriptedLlm`, сквозной `Phase4PipelineTest` (`analyze → collect → adapt` на фикстуре `bank-project`, проверка итогового Java-кода). Живой smoke против реальных MCP/DIAL — опционален.
  - Решение сессии: Этап 0 (глобальные компоненты) переносится в Фазу 5 как часть оркестратора, использует тот же `AgentLoop`.

- [x] **Фаза 5: Главный Оркестратор, Фильтр «3 из 3 PASS», Git-чекпоинты и `SelfHealingService`**
  - `MavenTestNgRunnerAdapter` (`infrastructure.maven`): команда из секции `maven` (`./mvnw` проекта или `mvn`, `-Pe2e`, `-pl`), удаление старого `testng-results.xml` перед каждым прогоном, разбор результатов (`TestNgResultsParser`: data-provider → FAILED если упал любой вызов, упавший `@BeforeMethod` → SKIPPED) и ошибок javac (`CompilerOutputParser`), таймаут → `ERROR` и убийство процесса с потомками (`ProcessCommandExecutor`), поиск улик падения `target/screenshots` и `target/page-source` (`FailureArtifactFinder`), `-DexcludedGroups` по платформе при прогоне класса.
  - `SelfHealingService` (`application.healing`): досье (стектрейс, скриншот, очищенный XML, исходники дерева вызовов, слепки, правила iOS, прошлые попытки), ограниченное исследование на живом iOS MCP (10 шагов / 60k токенов), structured-предложение Tier-1 (`HealingProposal`: корневая причина, `CodeChange`-правки, `learnedRule`), валидация (только классы дерева вызовов, не `BasePage`/`BaseTest`; `inspectBody`; локатор по XML экрана падения), одна повторная просьба в попытке, компиляция, откат к опорной точке с повтором прежних пакетов при `COMPILATION_FAILED`. `TEST_DATA` / `SHARED_FRAMEWORK` / `ENVIRONMENT` — без правок. `CompilationRepairService` — починка компиляции кодогенерации (Tier-1).
  - `StabilityGateService` (`application.stability`): серия `3/3` на iOS, лечение обнуляет серию, `SKIPPED`/`ERROR` повторяются без правок, бюджеты теста (`gate.max_test_minutes`, `gate.max_test_tokens`); `3/3` → `VERIFIED_STABLE` в кеше (шаги, локаторы, состояния, глобальные компоненты) + коммит `checkpoint:`; неудача → откат к опорной точке, `ios-needs-fix` и коммит `isolate:` для кодовых причин, `FAILED` не перетирает `VERIFIED_STABLE`, улики копируются в `migration_reports/<Class>/failures/<method>/`.
  - `TestClassMigrationOrchestrator` (`application.orchestrator`): Этапы 1 → 2 → 0 → 3 (компиляция с 2 попытками починки, иначе откат класса) → коммит `codegen:` → 4 → 5 (итоговый iOS-прогон, `AndroidRegressionGuard` с перезапуском упавших методов, отчёт, коммит, пуш). Статусы `MigrationExitStatus` (0/1/2/3), отказ на грязном дереве, остановка класса при недоступном окружении, продолжение существующей ветки. `GlobalComponentInitializer` (Этап 0: компоненты из `global_components` мапятся на слепки первого класса), `ProjectProgressCalculator`. Этапы за интерфейсами (`DeltaAnalyzer`, `SnapshotCollector`, `CodeAdapter`, `TestStabilizer`, `Healer`, `RegressionGuard`, ...).
  - Домен/порты: `MigrationStage.STAGE_4_SELF_HEALING`, учёт времени и вызовов LLM по тестам в `TelemetryCollector.testSnapshot`, `MavenConfig`/`GateConfig`/`global_components` в `EngineConfig`, `GitServicePort.uncommittedChanges`, `CodeAnalyzerPort.listScreenClasses`/`listLocatorFields`, новый `ArtifactStorePort` (`FileArtifactStore`), улики в `TestRunResult`. `ScreenshotListener` песочницы сохраняет и XML экрана; контракт с фреймворком — в `README.md`.
  - Тесты: парсеры на фикстурах, раннер с фейковым `CommandExecutor` и скриптом вместо `mvn`, `SnapshotGit` (git на копии фикстуры), сценарии шлюза и оркестратора, сквозной `Phase5PipelineTest` (вылеченный и изолированный тесты на реальных сервисах с фейковыми портами). Живой прогон на устройстве — опционален.
